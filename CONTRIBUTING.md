# Contributing to Farsio

Thanks for helping improve Farsio products.

## Engineering expectations

- Keep changes focused and reviewable.
- Preserve Persian/RTL behavior and consider LTR behavior where relevant.
- Keep browser permissions and data access minimal.
- Run documented validation/build commands before opening a PR.
- Update documentation when public behavior changes.
- Never include secrets, tokens, private keys, credentials or personal data.
- Do not mutate release tags or published artifacts in unrelated changes.

## Pull requests

Explain what changed, why it changed, how it was validated, user-facing impact, and security/privacy impact.
